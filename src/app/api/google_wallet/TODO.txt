Explanations:

Google wallet digital passes are *digital pass objects* stored on Google's servers.
Each digital pass must be tied to a *digital pass class*.

Process of issueing passes:
- Create digital pass class in advance of deployment
- When an authenticated member requires a membership pass (through some front end page):
    1. Make API call to create a *digital pass object* for that member. (Nothing happens if object already exists)
    2. Make API call to get an "add to wallet" link
    3. User adds pass to there wallet by clicking the link on their phone
- *Digital pass objects* can be updated without user interaction

So far what's been written:
- basic functions in "@/lib/wallet_integration" including:
    - "initialiseClass", which POSTs a hard coded *digital pass class* to Google's servers
    - "passFromMember", which creates a *digital pass object* for a given member
    - "linkFromMember", which signs a JWT linked to a member's *digital pass object* and returns an add to wallet link
- API route at /api/google_wallet, currently provides unauthenticated access to the above functions using a mock member.
